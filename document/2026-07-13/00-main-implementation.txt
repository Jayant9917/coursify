COURSIFY HANDAFF SUMMARY - 2026-07-13

This file is the fastest way to understand what the project is, what we already built, and what still needs to be done.

1. What Coursify is

Coursify is a course platform.
It is being built to support:
- public course browsing
- student accounts
- instructor accounts
- admin management
- course creation
- lesson building
- checkout and payment later
- uploads for avatars, thumbnails, and lesson files

The goal is to grow it from an early MVP into a client-ready course website.

Frontend safety and cleanup:

4. Important business logic now in the backend

The backend is now the source of truth for most important platform behavior:
- who can create/edit courses
- who can upload avatars or course thumbnails
- who can enroll
- how coupons are validated
- how discounts are calculated
- how refresh tokens are managed
- how password reset tokens are managed

This is important because the frontend should only send user intent.
The backend should decide what is valid.

5. Database design direction

We are using MongoDB collections for:
- users
- categories
- courses
- course sections
- lessons
- enrollments
- orders
- order items
- reviews
- wishlists
- course progress
- coupons
- notifications
- refresh tokens
- password reset tokens

For uploaded files:
- only URLs should be stored in MongoDB
- actual file binary should not go into the database

6. What is currently working in uploads

Password reset testing:

What is still not uploaded yet:

8. Main decisions already made

- MongoDB is the database
- React + Vite is the frontend
- Cloudinary is the image provider
- S3 will be used later for heavier files
- Lemon Squeezy will be used later for payments
- backend should stay the source of truth
- store only URLs for uploaded files
